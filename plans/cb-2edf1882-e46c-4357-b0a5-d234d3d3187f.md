# DAYZEROCTO-20 — Resolve the profile from the current repository

## Intent and bounded scope

When `--profile` is absent, select the global profile whose `codeRepos` contains the canonical top-level directory of the caller's current Git repository. Exactly one matching profile wins over `defaultProfile`; zero matches or a cwd outside Git preserves the existing default fallback. Two or more matching profiles must stop with status 2 before writes, emitting exactly `dzcto: <repo path> is listed in more than one profile (<a>, <b>); pass --profile` on stderr, with sorted names. An explicit profile wins without probing Git. A configured subdirectory does not match its containing repository.

Preserve all six issue acceptance criteria: unique match, default fallback (including outside Git), deterministic ambiguity/no writes, explicit-profile precedence, updated Step 1 in both report skills, and HOME-isolated tests for all five selection cases. No new configuration keys, dependencies, interactive CLI prompts, report schema changes, or consumer-repository edits. Existing explicit artifact-folder precedence remains intact; the selected profile still supplies profile metadata/evidence. Init with an explicitly supplied destination must retain its existing onboarding semantics.

The light lane is suitable: this changes local routing, not authentication, security policy, infrastructure or data storage semantics. No escalation or additional review stage is selected. The supervisor retains all configured checks and final independent code review.

## Implementation units

### U1 — Shared repository-aware selection

Add a small standard-library Git top-level discovery helper in `scripts/dzcto_artifact.py`, using `subprocess.run` with an argument list, captured output and no shell: `git rev-parse --show-toplevel` in the current cwd. On nonzero result or unavailable Git, return no repository and preserve default selection. Resolve the discovered path and each nonblank string `codeRepos` entry with `expanduser().resolve()`, then compare equality only. Do not query Git inside every configured path or use prefix/ancestor matching. Multiple entries in one profile count as one matching profile; collect matching profile names in a set and sort for the diagnostic.

In `profile_from_global(profile_name=None)`, return the existing explicit-name lookup before discovery. For implicit selection, return the unique profile, or preserve the existing default/legacy fallback for no match. On ambiguity print the exact issue diagnostic once and raise `SystemExit(2)` (a string-valued SystemExit would incorrectly exit 1). An internal exception translated at both CLI boundaries is also acceptable if it preserves these observable outputs. Avoid changing how profiles are normalized or how absent/unknown explicit names behave.
